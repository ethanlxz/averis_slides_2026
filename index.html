06 - Challenges

Hard part: be useful when documents are messy.

1
Messy formatsPDFs, Word files, spreadsheets, scanned pages, and inconsistent table layouts.
2
Meaning is not always literalEquivalent field labels and port formats must be normalized before comparison.
3
Accuracy over confidenceWhen unreadable or uncertain, Veritas should ask for review instead of guessing.
4
Deployment constraintsOCR and local files are heavy for serverless, so demo data should be preloaded.

What judges should see clearly

Veritas does not just say "AI checked it." It shows the request type, extracted evidence, SI value, BL value, mismatch field, confidence, reviewer action, and audit trail.

07 - Roadmap / How to deploy

Four phases to improve the current MVP.

1

Local MVP

Run FastAPI, import the bundle, classify emails, extract SI/BL fields, verify, and generate reports.

uvicorn + SQLite + loader.py
2

Accuracy hardening

Expand normalization, add OCR/vision fallback, and use self-evaluation plus unit tests to reduce false alarms.

EasyOCR + LLM evals + unittest
3

Demo deployment

Run heavy processing locally, preload Supabase, then deploy a fast read-only UI/API for judges.

Supabase Postgres + Vercel
4

Production scale

Add background workers, object storage, monitoring, reviewer roles, and model/version tracking.

RQ/Celery + S3/Supabase Storage
